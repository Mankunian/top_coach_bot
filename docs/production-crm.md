# CRM: серверная версия 1

## Обновление Railway

Сервис использует DATABASE_URL, если он задан. Docker устанавливает psycopg. При старте автоматически создаются таблицы и однократно копируются профили из SQLite (DB_PATH) в PostgreSQL; существующие записи PostgreSQL не перезаписываются. Не удалять SQLite/Volume до проверки профилей и резервной копии.

MINI_APP_URL остаётся прежним (/mini.html), повторно настраивать webhook не нужно. Корневой URL также открывает серверную Mini App. Локальный index.html на отдельном Python-сервере 4173 остаётся дизайн-прототипом; production API не отдаёт app.js с моковыми данными.

/health возвращает version=crm-1, database=postgresql. Если DATABASE_URL задан, ошибки PostgreSQL не переключают приложение молча на SQLite.

## Реализовано

- Авторизация подписанным Telegram initData, роль из регистрации, пустые списки без моков.
- Профиль; тренеры по городу; заявка игрока с комментарием; решение тренера.
- Поиск по группам и ученикам, создание группы с расписанием, добавление одобренного ученика с двух сторон, одна группа на ученика.
- Часы и оплаты в Учениках, история выручки за период. Идемпотентность оплаты по nonce, суммы в тиынах.
- Календарь: запланирована / идёт / завершена / отменена. Участники фиксируются в занятиях. Закрытые занятия не переписываются.
- Отсутствие за сутки, посещаемость тренером, отмена с причиной более чем за 24 часа. Очередь сообщений Telegram.
- Фоновое завершение и списание, нулевой баланс без долга, напоминания за 48/24 часа (трёхминутное окно, просроченные напоминания не рассылаются массово).
- Premium-заглушка выгрузки.

## Архитектура первого запуска и ограничения

CRM хранится в одной JSON-записи PostgreSQL под транзакционной advisory-блокировкой; это начальная реализация для двухаккаунтного теста, не нормализованная схема для большого числа тренеров. Пользователи, очередь сообщений и входящие update_id — отдельные таблицы. Все действия фильтруются по текущему Telegram ID. Одна реплика сервиса (отправщик outbox ещё не рассчитан на несколько реплик).

Расписание строится на 90 дней вперёд и продлевается обработчиком. Часовой пояс Казахстана UTC+5. Фактическая длительность — 1 час, согласно прототипу. Родитель пока представлен одним участником: отдельные карточки нескольких детей ещё не подключены. Фотографии, реальные подписки/экспорт, возвраты и корректировки исторических оплат — следующие этапы. Лимит пяти групп пока не применяется.

Миграция переносит зарегистрированные профили, не демоданные из браузера. PostgreSQL-соединение требует реальной проверки в Railway; локальные тесты используют SQLite. База не должна быть доступна из Mini App напрямую.

## Проверка с двух аккаунтов

1. После деплоя /health: crm-1 / postgresql.
2. Закрыть и заново открыть Mini App из бота; старый профиль тренера на месте, группы пустые.
3. Другой Telegram: игрок, тот же город; найти тренера, отправить заявку.
4. Тренер: принять, создать группу, добавить ученика, внести часы и сумму.
5. Игрок: увидеть группу, календарь и баланс. Проверить отмену участия на занятии более чем через сутки.
6. Тренер: отменить другое занятие с причиной, проверить сообщение обоим участникам.
7. Перезапустить сервис: данные должны сохраниться.

## crm-2: исправления по результатам проверки

- Возвращён недельный календарь, выровнена высота select/input, кнопка темы без переноса.
- Профиль игрока/родителя не показывает клуб и адрес. Поля остаются у тренера.
- Принятие заявки сообщает имя тренера и дальнейшие действия.
- Пополнение часов сообщает сумму, дату и баланс; повтор nonce не создаёт второе сообщение.
- Назначение группы сообщает название, место и ближайшую тренировку.
- Начало занятия уведомляет тренера и участвующих игроков один раз; завершённые/отменённые занятия не запускают такое сообщение.
- Имя ученика редактируется в списке тренера как локальное для этого тренера имя, без перезаписи Telegram-профиля и исторических оплат.
- Посещаемость сохраняется без закрытия диалога и сброса прокрутки.

## crm-3

Одно предварительное напоминание за 3 часа вместо 48/24. Начало и завершение уведомляют тренера и участников; завершение сообщает игроку списание и остаток, тренеру итог. Повторная обработка не дублирует события. Платёж и назначение группы по-прежнему создают уведомления.
Карточки групп/учеников переработаны, выручка содержит сводку и даты в одной строке, мобильная навигация имеет внешние отступы 10px плюс safe area. В принятых заявках возвращён Telegram-чат. Завершённые/отменённые занятия не показывают отмену; выход из диалога называется «Закрыть».

## crm-4
В истории оплат отображается текущая группа ученика по payment.player → group.members; если группы нет, выводится «Ученик пока без группы». Исторические поля платежа не изменяются. Вкладки групп и учеников показывают количество записей.

## crm-5

Компактные карточки групп открываются кликом и клавиатурой; меню действий независимо. Детали включают место, расписание, период, ближайшее занятие и учеников с комментариями/балансами. Подтверждение удаления описывает реальные последствия (история и деньги сохраняются).
Premium: расширенное описание базового функционала и планируемых платных преимуществ без обещания готового биллинга. Мобильные поля 16px, запрет масштабирования через viewport, Telegram fullscreen с проверкой версии, safe area, подтверждение закрытия и отключение вертикального сворачивания. Системные элементы и соблюдение viewport зависят от клиента Telegram/ОС.
Профиль тренера: корты из API по городу, очистка при смене города, автозаполнение адреса, ручной ввод. Сервер проверяет принадлежность выбранного корта городу. Алматы: 5 проверенных по доступной выдаче 2ГИС площадок (Максат, Эйс, Jan Dosym, ЦСКА, Adk), не полный экспорт каталога. Источник: https://2gis.kz/almaty/search/Тенисы ; проверено 2026-09-17.

## crm-6

Город фиксирован в профиле и проверяется сервером: смена пока запрещена. Для уже зарегистрированных закрепляется текущий сохранённый город (прежних изменений не откатываем). Корты в создании группы берутся по cityId тренера. Модальные формы ограничены по ширине, горизонтальный скролл отключён.
У игрока тренеры: Все / Мои тренеры, компактное описание и подробная карточка (ФИО, город, площадка, адрес, описание, заявка/чат). Placeholder профиля соответствует игроку. На главной тренера баннер Premium. У игрока рядом с часами сумма оплат текущему принятому тренеру за всё время, из серверных платежей; чужие оплаты не выдаются.
Бэклог: прикрепление сертификатов в профиле тренера и просмотр в подробной карточке.

## crm-7
Игрок и родитель завершают регистрацию после города, площадка только для тренера. Новая заявка в боте: ФИО, город, комментарий и web_app-кнопка с page=requests. Роль проверяется при открытии: игрок не попадает на экран тренера. Автообновление открытых списков каждые 5 секунд и при возвращении в приложение; без перерисовки во время ввода и открытого диалога. В заявках также кнопка ручного обновления. Обновление сохраняет вертикальную прокрутку.
