# Telegram: первый серверный этап

Реализованы бот регистрации (тренер / игрок / родитель), имя из Telegram, город по UUID, выбор клуба по городу, ручная площадка/пропуск, сохранение в SQLite, Mini App профиля с проверкой подписи initData. /start после регистрации открывает приложение, не создаёт пользователя заново. Роль родителя пока регистрирует взрослого: карточки детей следующим этапом.

API: GET /api/cities; GET /api/venues?cityId=<UUID>; GET /api/me; POST /api/me. Последние два требуют X-Telegram-Init-Data. Каталог у API и бота общий, запросы HTTP внутри самого сервиса не нужны.

Регистрация и профили — реальные серверные данные. Основная CRM на /index.html остаётся локальным демонстрационным приложением. Бот открывает /mini.html, без подмешивания чужих моковых учеников. Следующий этап: перенос CRM-данных в API с изоляцией по тренерам, затем серверные тренировки, уведомления и списания.

## Запуск

Python 3.9+ (Docker: 3.12), внешние зависимости не нужны.

```sh
python3 -m backend.server
python3 -m unittest discover -s tests -v
```

Сервер по умолчанию на 8080. Локальный запуск без BOT_TOKEN проверяет API; отправки в Telegram нет. SQLite локально в .data, каталог не публикуется и исключён из git. Файл .env автоматически не читается; передавайте переменные окружения через платформу/терминал.

## Railway: один сервис, одна реплика

1. Развернуть этот проект через Dockerfile.
2. Добавить Volume с mount path /data; DB_PATH=/data/topcoach.sqlite3. Настроить резервные копии. Не запускать несколько реплик этой версии с SQLite/outbox.
3. Добавить BOT_TOKEN из BotFather и WEBHOOK_SECRET (случайная строка 32+ символов) в Variables. Не коммитить их.
4. Создать HTTPS-домен сервиса, задать PUBLIC_URL=https://<domain>, MINI_APP_URL=https://<domain>/mini.html.
5. После запуска выполнить в окружении сервиса `python -m backend.setup_bot`: описание, команды, кнопка меню, webhook с секретом. Этот шаг отправляет запросы в Telegram и требует реального токена.
6. Проверить /health, затем в личном чате бота пройти /start, регистрацию и открыть профиль. Проверить сохранение после перезапуска сервиса.

В Railway.json настроен /health. Исходный фронт на порту 4173 продолжает работать отдельно для дизайн-проверки. Продакшн-развёртывание пока не выполнено: нужны бот и доступ к Railway.

## Доставка

Webhook проверяет секрет и дедуплицирует update_id; изменение регистрации и очередь ответов сохраняются в одной транзакции. Очередь повторяет неудачные отправки до 10 раз. После исчерпания попыток требуется разбор/повтор оператором. При сбое между успешной отправкой и фиксацией возможен повтор сообщения (ограничение at-least-once). Внешние отправки пока не проверены реальным токеном.
